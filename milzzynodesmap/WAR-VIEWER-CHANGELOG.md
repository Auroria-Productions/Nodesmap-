# MilzzyNodesMap public war viewer integration — 0.3.4

## Added

- `web/war-systems.js`: tested compatibility adapter for classic flag war, NodesWar,
  key-point wars, warzones, and raids.
- Independent public `data/nodes/war-systems.json` feed updated every five seconds,
  generated by `WarSystemsPublisher` from Nodes config and allowed battle state files.
- Separate war-panel sections for each enabled subsystem, with live status, stronghold
  coordinates, attacker/defender, elimination counts, and click-to-fly for key points.
- Key-point battle icons as a viewer-only Leaflet layer.
- Clear UI for one-life key-point rules: respawn with war sickness, no re-entry,
  staff-mediated peace terms, no automatic territory capture.
- No new interactive controls in the editor, and no changes to the editor's JS/HTML.
- Public battle payload whitelist; internal staff fields and player lists are not published.
- Legacy `live.json` fallback for existing Nodes installations.

## Scope and limitations

- This is a **map viewer presentation/export change**, NOT a replacement for the
  key-point war gameplay implementation in your Nodes core.
- Built against available NodesMap 0.3.3 Paper source, producing map JAR version 0.3.4.
- The linked ChatGPT share itself was inaccessible for byte-for-byte verification.
  Keep your most recent Nodes core build with the correct gameplay rules.
- This package has not been tested on a live Minecraft Paper server; Java and JS
  checks passed locally, including NodesMap's existing territory publishing smoke.
- If the newest Nodes core uses different config keys or JSON battle data fields,
  adapt `WarSystemsPublisher` and `war-systems.js` to match the final core schema.
